# 组件写法范式（`rsx!` + `#[component]`）

这份文档回答三个问题：

1. `#[component]` 到底怎么用？为什么 finance 里看不到统一套路？
2. ooc 里的 `ctx` 在 Rust 这边的对应物是什么？
3. 信号该放哪？为什么 finance 的 `Model` 越来越小？

对照实现：`crates/wy-app/examples/finance/ui/`（声明式参考实现）。
另一份已按本范式改写的示例：`crates/wy-app/examples/shadcn/`（见第 ③.5 节对照）。
运行：`cargo run -p wy-app --example finance` / `cargo run -p wy-app --example shadcn`。

---

## 0. 一句话模型

> 树只建一次；信号变 → 重绘；组件是**函数**，返回值是节点。

- 没有虚拟 DOM diff，没有 `setState` 瀑布。`rsx! { .. }` 在**组件函数被调用时**
  执行一遍，产出一棵 `Node` 树，之后只重绘。
- 所以 `rsx!` 里写的是**结构**（谁是谁的孩子），不是**每一帧的逻辑**。
- 会变的东西（文字、颜色、显隐）一律写成闭包，绘制期求值。

---

## 1. 四种套路，覆盖 95% 的组件

### ① 匿名组件（自绘 + 嵌套）：`node { draw: .., ..children }`

`node` 就是你要的「匿名类」——不需要名字、就地定义、就地使用，对应 Kotlin 的
`object : Node() { override val … }` / `Box { drawBg(); content() }`。

- **动态属性自动是 getter**：`node` 上的每个属性表达式（`width: gap.get()`）都会由宏
  自动包成 `*_fn`，绘制期按帧重算——这就是 `#[getter]` 的语义，在 `node` 上**已内置**，
  不用再写注解。
- **既能画自己，也能装子组件**：不带子节点时是纯叶子（尺寸取声明值 / `measure`）；
  带子节点时子组件按 `Column` 排进它的布局盒，`draw` 画背景、子节点叠在上层，
  一个「卡片 / 面板」就出来了，`#[component]` / `for_each` 都能平滑嵌套进来。

```rust
fn card() -> Node {
    rsx! {
        node {
            width: 240.0,
            padding: 12.0,
            draw: |s: &mut Scene| {            // 画背景（current_box 读自身尺寸）
                let b = current_box();
                s.fill_round_rect(Rect::new(0.0, 0.0, b.width, b.height), 8.0, theme::PANEL);
            },
            label("标题")                         // 子组件直接嵌套进来
            vbox { label("行 1") label("行 2") }  // 甚至再嵌容器
        }
    }
    .into_node()
}

fn vsep() -> Node {                              // 纯叶子形态（无子节点）依旧可用
    rsx! {
        node {
            width: 1.0,
            height: 16.0,
            draw: |s: &mut Scene| {
                let b = current_box();
                s.fill_rect(Rect::new(0.0, 0.0, 1.0, b.height), theme::BORDER);
            },
        }
    }
    .into_node()
}
```

> 形态对照：`node {}` = **匿名、内联**组件（Kotlin 匿名类）；`#[component] fn` = **具名、可复用**
> 组件。两者进的是同一棵树，后者靠 `builder` 收 props、前者靠就地属性表达式。
> 别把 `node` 当成「只能画自己的特殊东西」——它就是一个能自绘的容器节点。

### ② 组合：容器 + 子组件

```rust
fn source_switch(model: Rc<Model>, ctl: Rc<Ctl>) -> Node {
    rsx! {
        hbox {
            gap: 4.0,
            width: 128.0,
            height: 22.0,
            align_items: AlignItem::Center,
            draw: |s: &mut Scene| { /* 外框 */ },
            { source_seg(model.clone(), ctl.clone(), Source::Binance) }
            { source_seg(model.clone(), ctl.clone(), Source::Mock) }
        }
    }
    .into_node()
}
```

- `{ expr }`：块表达式子节点，求值结果是 `Node` 或 `Slot`。
- `..vec`：把动态子节点列表拼进容器（`..symbol_tabs`）。
- 文本可以直接写字面量，子节点写组件标签。

### ③ 组件：`#[component] fn xxx(..)` → 在 `rsx!` 里当标签用

```rust
#[component]
pub fn text_label(
    /// `#[getter]`：显示值语义——调用处传裸表达式或闭包皆可
    #[getter] content: String,
    /// 不能叫 `size`：那是通用布局属性（`(w, h)`），会撞车
    font_size: f32,
    /// 颜色也用 getter：裸 `Color` 或闭包都行
    #[getter] color: Color,
) -> Node { /* .. */ }

// 调用处：不用再写 `move || ..`，裸值/闭包自动按帧重算
rsx! {
    text_label {
        content: title,            // 裸值或闭包皆可（这里传现成的取值闭包 Rc）
        font_size: 12.5,          // 静态值仍按原样
        color: theme::TEXT,        // 裸 Color 自动包成取值闭包
        grow: 1.0,                // 组件和容器一样是布局节点
    }
}
```

`#[component]` 做的事：把函数签名改写成 `fn(Props)`，并生成
`Props::builder()..build()`。**调用处不用写 Props 类型名**。

**`#[getter]` 显示值注解**（本节重点）：在 prop 上标 `#[getter]`，它的 setter 就收
`impl IntoGetter<T>`（`wy_mve::IntoGetter`）。调用处——

- 传**裸值**（`"BUY"` / `model.x.get()` / `theme::TEXT`）→ 自动包成 `move || 值`，
  每次重绘按帧重算；
- 传**闭包**（`|| ...`）→ 原样使用。

这正是你想要的效果：**把 button 的 label 这类动态属性写成表达式即可，不必再手写
`move || ...` 样板**，对应 ooc 里「属性即表达式、每次 recomposition 重算」的写法。

已实现 `IntoGetter` 的裸值类型（含全部有符号 / 无符号整数）：

- 文本：`String` / `&'static str`
- 浮点：`f32` / `f64`
- 整数：`i8` `i16` `i32` `i64` `u8` `u16` `u32` `u64` `usize`
- 其它：`bool` / `Color`

外加任意 `F: Fn() -> T` 闭包与已有的 `Rc<dyn Fn() -> T>`。其余类型按需往
`wy_mve::getter` 模块补一条 `impl` 即可。

**整数字面量也能直接当 getter**——变体号、索引、状态码这类小整数最典型
（`badge` 的 `variant: u8` 即此用法）：

```rust
// variant 是 `u8` 的 #[getter]，调用处传裸字面量即可（自动包成 move || 1）
rsx! { badge { text: "LIVE",   variant: 1 } }
rsx! { badge { text: "v0.1.0", variant: 3 } }
```
不是 getter 的 prop（静态值 `font_size`、`children`、`on_click` 等事件）维持原语义。

三条实用规则：

| 规则 | 原因 |
| --- | --- |
| 组件只能在 `rsx!` 里当标签调用 | 宏改写签名后，函数本身已变成 `fn(Props)` |
| 参数别叫 `size` | `size` 是通用布局属性（`(w,h)`），会撞车 |
| `on_click` 等事件名走 props，不进布局属性 | 否则节点回调设上了、props 空着，组件收不到点击 |
| 动态显示属性加 `#[getter]` | 调用处就能写裸表达式，不必手包 `move \|\|` |

### ③.5 过程式 → 声明式：shadcn 改造对照

`examples/shadcn` 原本是一堆「过程式组合」：用 `wy_mve::vbox(vec![..])` 拼盒子、
手动挂 `.draw_fn` / `.measure_fn` / `.hit_test_fn`、还要手算子节点 `x`/`y` 偏移。
现已全部改写成「声明式 `#[getter]` + `node {}` 容器」，与 finance 同一套范式：

| 组件 | 改造前（过程式） | 改造后（声明式） |
| --- | --- | --- |
| `card` | 两层 `vbox` + 手动 `draw_fn` 背景 + 手算子节点 `x/y` | `node { padding, align_items: Stretch, draw, ..children }`，尺寸由调用处 `width`/`height` 决定 |
| `badge` | `(theme, text: impl Fn()->String, variant: impl Fn()->u8)` | `(theme, #[getter] text: String, #[getter] variant: u8)`，`width` 由 `measure_text` 算、裸字面量 `variant: 1` |
| `button` | `label: impl Fn()->String` + `make_button` 过程式 | `#[getter] label: String`，共用 `button_node`：`node { width, height, on_click, on_hover, on_down, on_up, draw }` |
| `text_label` | `(content: impl Fn()->String, font_size, theme, color: impl Fn(&Tokens)->Color)` | `(#[getter] content: String, font_size, #[getter] color: Color)`（去 `theme` 参数） |

要点：

- **`node {}` 既是自绘叶子又是可嵌套容器**——`card` 不再需要两层 `vbox` 自己叠自己，
  直接用 `padding` 让内容真内缩、`align_items: Stretch` 让子节点撑满宽度。
- **getter 是 `Rc<dyn Fn>`**——同一个 getter 被 `draw` 与 `measure`（或 `width` 与 `draw`）
  两个闭包各捕获一份时，要先 `Rc::clone` 出独立副本，否则第二次 `move` 编译报错
  「`Rc does not implement Copy`」。
- **布局属性定尺寸**——`card` 的宽高交给调用处 `width:`/`height:`，`node_size` 对容器
  优先用声明尺寸，卡片尺寸正确、且组件内不用写死。
- **事件名走 props，不进布局属性**——`on_click` 等仍是普通 prop（如 `button` 的
  `on_click: impl Fn()`），不要误塞进 `node` 的布局属性里。

### ④ 循环列表：`for_each`

```rust
let rows = for_each(
    move |emit| {                       // 数据源：读信号，emit(key, value)
        for (i, row) in view.iter().enumerate() {
            emit((bid, i), *row);
        }
    },
    move |_key, row, cx| cx.child(book_row(model.clone(), row)),  // keyed：按 key 复用
);
```

行高由父容器 `grow: 1` 均分——面板被拖矮时行自动收窄，
不需要在面板里反算行号行高。

### ⑤ 滚动容器与浮层：`scroll` / `dialog` / `dropdown`

复刻 Kotlin `wy-helper` 的 `SimpleScrollNode`/`DialogBase`/`DropdownBase`，
都是 `wy_mve` 自带组件（内部用 `clip` + `not_in_layout` + `on_key` 搭建）：

```rust
use wy_mve::{scroll, dialog, dropdown};

// 滚动容器：h 只是名义尺寸（flex 自然尺寸），超出即可滚动；
// 配 grow 即可填满父容器剩余高度（几何按每帧分配的布局盒实时计算）
scroll {
    h: 48.0,
    grow: 1.0,
    gap: 0.0,
    todo_row(theme, app)
    todo_row(theme, app)
}
// 滚轮驱动 + 溢出裁剪（看不见的也点不到）+ 浮动滚动条（无溢出自动隐藏）；
// 嵌套滚动：内层到边界后放行给外层（滚轮冒泡）

// 模态对话框：遮罩 + 居中面板；Esc / 点遮罩关闭，点面板不关闭。
// 浮层根不声明尺寸 → 自动撑满父容器（顶层即铺满窗口，缩放跟随）
dialog {
    open: move || app.dialog_open.get(),
    on_close: move || app.dialog_open.set(false),
    surface: move || theme.tokens().card,
    border: move || theme.tokens().border,
    text_label { content: "确认删除？" }
}
// 打开期间 focus_trap 圈定 Tab；Esc 靠引擎的全局按键广播，不依赖焦点位置

// 下拉菜单：面板锚定动态坐标（触发按钮的 on_click_ev 里捕获锚点）
node {
    on_click_ev: move |ev: &mut PointerEvent| {
        anchor.set((ev.root_x - ev.x, ev.root_y - ev.y));  // 按钮绝对坐标
        menu_open.set(true);
    },
    // ...
}
dropdown {
    open: move || app.menu_open.get(),
    anchor_x: move || anchor.get().0,          // 不叫 x/y：那是通用布局属性
    anchor_y: move || anchor.get().1 + 38.0,
    on_close: move || app.menu_open.set(false),
    surface: move || theme.tokens().card,
    border: move || theme.tokens().border,
    menu_item(theme, app, "重命名看板")
}
```

浮层的关键机制：`not_in_layout` 脱离父容器布局流、**文档序最后声明**
（绘制在最上层、命中最先命中——引擎对顶层节点倒序 hit test）；
关闭即整体 `hide`，不占布局也不拦事件。浮层根未声明尺寸时引擎自动
分配父容器内区（顶层即窗口大小），无需传窗口尺寸。

### ⑤.5 响应式布局：grow / Stretch / flex-basis 0

窗口缩放跟随的三板斧（见 shadcn `dashboard/mod.rs`）：

1. **根节点不写 `width`/`height`**——引擎把视口尺寸作为根的可用空间，
   顶层自绘用 `current_box()` 取实际尺寸；
2. **每层容器 `align_items: Stretch` + 子项 `grow: 1.0`**——默认对齐是
   `Center`，漏一层整条链就塌回自然尺寸（下游 grow 全部算出 0）；
3. **等分一行时给卡片 `size: (0.0, 0.0)`**（flex-basis 0）——grow 是
   "自然尺寸 + 按权重分剩余"，内容自然宽不同就不完全等宽；
   尺寸归零后完全由 grow 均分。

引擎配套（**两个都要做，缺一个布局就不跟随**）：

1. `WindowEvent::Resized` 置 `needs_redraw` 并请求重绘；
2. **视口尺寸必须是「被绘制追踪的信号依赖」**——绘制侧用 `RecordMemo`
   缓存整帧 Scene，只在依赖变化时重录。若视口只是普通 `Cell`，
   resize 后重绘请求会被短路、复用旧 Scene，画面停在旧尺寸
   （`MveApp::viewport` 用 `Signal<(f32, f32)>`，`draw` 里读一次即注册依赖）。

组件/容器在事件期可通过 `node.last_box()` 读上一帧实际分配的布局盒
（scroll 的滚动上限、滑块几何、浮层翻转都靠它）。注意 `last_box` 是
`Rc<Cell<..>>`——**必须共享**，否则引擎写树里的克隆、组件读自己手里的
克隆，两者永远对不上（`Node::clone` 要 `Rc::clone` 而不是值拷贝）。

### ⑤.6 图标：用矢量路径，别用字符

早先图标用 `✕ ✓ ▾ ▲ ▼ ≡` 这类**字符**绘制。字形是否存在**取决于系统
字体**：字体缺该字形时，渲染出来是空心方块（"豆腐块"），界面上就
表现为"一堆方块"——而且换台机器表现还不一样。

现在图标一律是**自绘矢量路径**（`wy_mve::Icon` + `Scene::fill_path` /
`stroke_path`），与字体完全无关：

```rust
use wy_mve::{icon, Icon};

icon { name: Icon::ChevronDown, size: 14.0, color: move || t.muted_fg }
```

在组件自己的 `draw` 里直接画（不想再嵌一层子节点时）用
`Icon::icon_paths()` + `Scene::fill_path/stroke_path`。

**判断标准**：界面上出现"方块"→先查是不是用了字符当图标。

## 2. `rsx!` 属性速查

| 属性 | 值 | 说明 |
| --- | --- | --- |
| `width` `height` `gap` `grow` | 字面量 / 表达式 | 表达式会包成 `*_fn`，**信号驱动** |
| `padding` `justify` `align_items` `align_self` | 枚举 / f32 | flex 排布 |
| `hide` | bool 表达式 | 为真时整体隐藏（不占位） |
| `size` | `(w, h)` 表达式 | 覆盖自然尺寸；配合 `grow` 作 flex-basis 0（等分行，见 ⑤.5） |
| `measure` | `(w, h)` 表达式 | 文本类必填，否则父容器按 0 宽排布 |
| `draw` | `\|s: &mut Scene\|` | 自绘；**别同时设 `skip_draw: true`**（会被跳过） |
| `on_click` `on_hover` | `\|\|` `\|bool\|` | 容器上挂节点回调；组件上就是 props |
| `on_move` | `\|f32, f32\|` | 悬停移动的**节点局部**坐标 |
| `on_wheel` `on_wheel_ev` | `\|ev\|` | 后者吃掉事件，不冒泡 |
| `on_down` `on_up` `on_drag_move` | `\|ev\|` | 拖拽三件套 |
| `on_key` | `\|ev: &mut KeyEvent\| -> bool` | 键盘事件；返回 true 表示已消费。焦点链未消费时引擎会**全局广播**（浮层 Esc 关闭不依赖焦点位置） |
| `on_click_ev` | `\|ev: &mut PointerEvent\|` | 带事件的点击（`stop_propagation()` 拦冒泡用） |
| `clip` | bool | 裁剪子树（overflow hidden）：绘制与命中都以布局盒为界，滚动容器用 |
| `not_in_layout` | bool | 绝对定位（Kotlin `notInLayout`）：不参与 flex 与自然尺寸，`x`/`y` 直接定位；**宽高均未声明时自动撑满父容器内区**（浮层铺满窗口）；浮层/滚动条用 |
| `tag` | `&'static str` | 语义标签：给节点起名，测试按名字精确定位控件（同类控件多时比按几何特征找可靠得多） |

`grow: split.get()` 这种写法是分割条拖动的全部实现——拖动改的是**权重**，
不是坐标，所以窗口怎么缩放都不会溢出。

## 3. ooc 的 `ctx` 对应物：`ctx: &mut NodeContext`

**结论：Rust 这边有对应物**——`#[component]` 的首参写成 `ctx: &mut NodeContext`
即可。它对应 ooc `fc $ [ctx, ... => ...]` 的那个 `ctx`。

### 3.1 机制：body 推迟到挂载期

```rust
#[component]
fn rows(ctx: &mut NodeContext, source: impl Fn() -> Vec<String>) {
    ctx.consume::<Rc<Model>>();                 // ① 读上层 provide 的值
    ctx.render_for_each(                        // ② 动态区域
        move |emit| { for s in source() { emit(s.clone(), s); } },
        |_k, item, cx| cx.child(label(move || item.borrow().clone())),
    );
}
// 调用处看不见 ctx：rsx! { rows { source: move || data.get() } }
```

宏把 body 包进 `ChildArg`（`FnOnce(&mut NodeContext)`）**推迟到挂载期执行**，
由框架把父容器的上下文递进去。所以 body 里能 `ctx.child(..)` 往父容器注入节点
——组件不再"返回一个节点"，而是"往父容器里放节点"。

`ctx` **不进 Props**：builder 里没有它，调用处也看不到它。

### 3.2 body 两种写法

```rust
// A. 纯注入：返回 ()，节点自己放进父容器（可多个）
#[component]
fn pair(ctx: &mut NodeContext) {
    ctx.child(label(|| "a".into()));
    ctx.child(label(|| "b".into()));
}

// B. 产出节点：返回 Node / Slot，框架帮你注入
#[component]
fn titled(ctx: &mut NodeContext, title: String) {
    ctx.child(label(move || title.clone()))
}
```

`IntoSlot` 为 `Node` / `Slot` / `ChildArg` / `()` 都做了实现，两种可以混用。

### 3.3 `ctx` 上能干什么

| 方法 | 用途 |
| --- | --- |
| `ctx.child(..)` / `add_node` | 注入子节点（可以多个） |
| `ctx.render_for_each(keys, render)` | 信号驱动的动态列表 |
| `ctx.render_when(cond, branch)` | 条件区域 |
| `ctx.provide(v)` / `ctx.consume::<T>()` | 上下文透传，见第 4 节 |

### 3.4 三条约束

1. **必须首参**，且类型正好是 `&mut NodeContext`；放后面或拼错类型会编译报错。
2. **带 `ctx` 就别再声明 `children` 参数**——两种注入方式互斥。
3. body 被搬进了闭包，**别在里头 `return` 提前退出**（报错位置会很反直觉）。

### 3.5 判断标准

> 组件需要"从上下文取值"或"往父容器注入动态区域"吗？

需要 → 用 ctx 组件。只是画自己、返回一棵静态子树 → 普通组件（返回 `Node`）就够，
而且更直观。finance 里六个面板全是 ctx 组件（要 `consume` 共享行情），
工具栏的小按钮仍是普通组件。

## 3.5（补）`provide` / `consume`：跨层级透传

**只在"真跨层级"时用**。参数能说清的就传参数；一层层往下递同样一份东西、
或者深层节点（比如 `for_each` 的行）够不着外层局部变量，才用它。

```rust
// 装配层：提供一次
#[component]
pub fn dashboard(ctx: &mut NodeContext, model: Rc<Model>, ctl: Rc<Ctl>) {
    ctx.provide(Rc::clone(&model));
    ctx.provide(Rc::clone(&ctl));
    ctx.child(page);
}

// 面板：只声明"我要什么"，不接 prop
#[component]
pub fn chart_panel(ctx: &mut NodeContext) {
    let model = ctx.consume::<Rc<Model>>().cloned().expect("dashboard 应 provide");
    ...
}

// 面板再 provide 自己的局部状态给行（for_each 项拿不到外层局部变量）
ctx.provide(Rc::clone(&book_state));
// 行里：
let b = cx.consume::<Rc<BookState>>().cloned().expect("book_panel 应 provide");
```

作用域语义：

- 子节点**继承父链的快照**——嵌套容器、`for_each` 的每一项都拿得到；
- 组件内 `provide` **只覆盖自己这一支**，不污染后面的兄弟；
- 按**类型**取值（`Rc<Model>`、`Rc<Ctl>`…），同类型后者覆盖前者。

两个坑：

| 现象 | 原因 |
| --- | --- |
| 深层 `consume` 返回 `None` | 中间某处对 ctx 组件调了 `.into_node()`——它会在**空白上下文**里立刻执行 |
| 组件标签上的 `grow` 没生效 | 见第 6 节：属性对 ctx 组件同样生效，但要保证没走 `.into_node()` |

## 4. 信号放哪：有第二个读者才提升

### 判据

> 一个信号只要**两块以上**的面板/控制器要读，才提升到 `Model`。
> 否则 `Signal::new` 在组件里，随组件创建、随组件持有。

### finance 的现状

`Model`（真跨面板，才提升）只剩这些：

```text
symbol / interval                          顶栏写，图表/盘口/统计读
ticker / klines / depth / trades / watch   后台线程写，多块面板读
status / error / source                    控制器写，顶栏读
```

已经下沉、不在这里的（以及它们现在的去处）：

| 原字段 | 现在在哪 | 下沉手法 |
| --- | --- | --- |
| `visible` / `offset`（K 线视口） | `ui::chart::ChartState` | **带 key 的惰性失效**：存 `(key, visible, offset)`，`key = 标的\|周期`，读的时候比对，换标的自动回默认视口——不再需要控制器记得 `offset.set(0)` |
| `picked_price`（点价） | `ui::book::BookState::picked` | 同上，带 symbol 的 key，换标的自动失效 |
| `depth_full`（FULL） | `ui::mod::dashboard` 的局部信号 | 装配层自己持有，当成一个 `Signal<bool>` 传给深度面板 |
| `chart_hover` / `depth_hover` / `zoom` | 各自面板的局部信号 | 只有一个读者，直接就地 `Signal::new` |
| 8 个 `book_*` 开关 | `ui::book::BookState` | 同上 |

`ui::book::BookState`（面板私有，不提升）——8 个开关 + 点价：

```rust
pub struct BookState {
    pub model: Rc<Model>,           // 共享的那部分照样传进来
    pub mode: Signal<BookMode>,     // 显示模式
    pub step: Signal<f64>,          // 聚合步长
    pub cumulative: Signal<bool>,   // 深度条口径
    pub rounding: Signal<bool>,     // Total 列收不收 K/M
    pub ratio: Signal<bool>,        // 底部 B/S 条
    pub avg: Signal<bool>,          // 均价合计行
    pub anim: Signal<bool>,         // 深度条动画
    pub menu: Signal<bool>,         // 设置条展开
    picked: Signal<Option<(String, f64)>>,  // 点价：带标的，换了就作废
}
```

`ui::depth_view::DepthState`——`zoom` / `hover`（外加一个外面传进来的 `full`）；
`ui::chart::ChartState`——`viewport` / `hover`。

### 为什么"提升"是坏事

把这些塞进 `Model` 的后果，每一项都是真付过的代价：

1. **换数据源要挨个重置**——`Ctl::set_source` 里曾经排了四行
   `model.chart_hover.set(None)` 之类的清理。局部化后这些行直接消失。
2. **写测试要造一个完整 `Model`**——现在盘口面板的显示偏好跟造测试数据无关。
3. **想复用面板得先接受它带的十几个字段**——`BookState` 可以单独构造、单独测试。
4. **每加一个"应该重置"的入口就要补一行清理**——换标的、换周期、换数据源……
   漏一处就是一个"停在上一只票的偏移上"的 bug。带 key 的惰性失效把这类耦合
   整类消掉了。

### 什么情况下必须提升

- 有第二个读者（`symbol` / `interval`：顶栏写、图表和统计读）。
- 后台线程要写、多块面板要读（行情数据本身）。
- 要切换整棵子树又不值得为此开一条上下文——那就退一步：由**装配层**持有一个
  局部信号，当成普通 prop 传给需要的面板（`depth_full` 的做法）。

## 5. 一份最小可运行组件

把下面存成 `ui/demo.rs`，在 `ui/mod.rs` 里加一行即可看到效果：

```rust
use std::rc::Rc;
use wy_mve::{component, current_box, rsx, AlignItem, Node};
use wy_render::{Rect, Scene};
use wy_signal::{GetValue, SetValue, Signal};

/// 计数器：点一下 +1，自己管自己的数。
#[component]
pub fn counter(start: i64) -> Node {
    let n = Signal::new(start);          // 局部信号，不进 Model
    rsx! {
        node {
            width: 96.0,
            height: 28.0,
            align_self: AlignItem::Center,
            on_click: move || n.set(n.get() + 1),
            draw: move |s: &mut Scene| {
                let b = current_box();
                s.fill_round_rect(Rect::new(0.0, 0.0, b.width, b.height), 6.0,
                    wy_render::Color::from_u32(0x2A3446FF));
                theme::text_center(s, b.width / 2.0, 9.0, &n.get().to_string(), 11.0,
                    theme::TEXT);
            },
        }
    }
    .into_node()
}
```

要点全在这里：一个函数、一个局部信号、一次 `rsx!`、绘制期读 `current_box()`。
没有继承、没有生命周期标注、没有手算坐标。

## 5.5 列表状态：结构信号 + 每项独立信号（别退回 React）

一个列表要区分两类状态：

- **结构**（有哪些项、什么顺序）——增删时变；
- **每项内容**（这一项的文本、勾选态）——改一项时只变这一项。

把两者塞进**一个** `Signal<Vec<Item>>` 是 React 式写法：
勾选一项要重写整个 Vec → 列表 memo 的依赖变了 → 整张列表重算。

MVE 的做法（shadcn `todos.rs` 是范例）：

```rust
// 结构：只管 id 顺序
pub todo_ids: Signal<Vec<u32>>,
// 每项：独立信号，勾选只写这一个
pub todo_store: TodoStore,   // id -> Signal<bool> / Signal<String>
```

行节点在**绘制期**读自己那项的信号：

```rust
text_label { content: move || row_text.get() }
```

于是勾选一项的影响面精确到一行——这才是 Kotlin MVE 的
`EachValue` + per-item signal 模型。

配套注意：

- 筛选信号必须在 `for_each` 的**源闭包内**读（memo 求值时执行），
  否则 memo 追踪不到，改筛选不重算；
- `for_each` 的 `creater` 只对**新 key** 执行，复用项的节点不重建。

## 6. 常见坑

| 现象 | 原因 |
| --- | --- |
| 节点宽度 0、画不出也点不中 | 忘了 `align_items: Stretch`，或文本忘了 `measure` |
| `grow` 行塌成 0 | 面板内容外包了一层 vbox，多出一个"自然高度"的盒子 |
| 窗口放大布局不跟随 | 响应链某层忘了 `align_items: Stretch`（默认 Center，下游 grow 全算 0）；或根节点写死了 `width`/`height` |
| 等分一行宽度差几像素 | grow = 自然尺寸 + 均分剩余；给卡片加 `size: (0.0, 0.0)`（flex-basis 0） |
| 组件在事件期拿不到实际尺寸 | 读 `node.last_box()`（引擎绘制期写入）；构建期常量在 grow/Stretch 下必然失真 |
| 标题被按钮压住 | 在 `draw_fn` 里按 `w - PAD` 反算徽标位置；应改成 flex 兄弟节点 |
| 按钮/分割条不显示 | 给带 `draw_fn` 的节点设了 `skip_draw: true` |
| 拖动看不出变化 | `grow: 0.4` 写成了字面量；要写 `grow: split.get()` |
| `⋯` / `✕` / `✓` 变成豆腐块 □ | 字体没有该码位；改用矢量图标（`wy_mve::Icon`，见 ⑤.6） |
| 卡片高度塌成 0、内容溢出 | `size: (0.0, 0.0)` 早期是**整体覆盖**自然尺寸，把高度也清零了；现改为**逐维覆盖**（0 表示该维不设固定值） |
| 列表项整条居中 | 默认 `align_items: Center`；列表容器要显式 `align_items: Stretch` |
| 改筛选后列表不变 | 筛选信号在 `for_each` 的 memo **之外**读，memo 追踪不到；必须写在源闭包里 |
| 勾选一项导致整张列表重算 | 状态装在一个 `Signal<Vec<T>>` 里（React 式）；改用「结构信号 + 每项独立信号」 |
| 窗口放大后画面停在旧尺寸 | 视口尺寸不是**被绘制追踪的信号依赖**，绘制缓存复用旧 Scene（见 ⑤.5） |
| 浮层下方没空间、面板看不见 | `dropdown` 现在按可视区自动翻转（下方不够就向上弹），并横向钳制在窗口内 |
| `last_box()` 读到 0 | `last_box` 必须是 `Rc<Cell>`（跨克隆共享）；值拷贝的 `Cell` 永远对不上 |
| 组件在事件期拿不到实际尺寸 | 读 `node.last_box()`（引擎绘制期写入）；构建期常量在 grow/Stretch 下必然失真 |
| `Rc<dyn Fn>` 传给 `impl Fn` 参数报错 | 包一层：`move \| f()` |
| 组件标签里 `on_click` 没反应 | 它被当布局属性截走了；事件名必须走 props |
| ctx 组件在 `rsx!` 里"消失了" | body 忘了 `ctx.child(..)`：只 `panel_with(..);` 的话节点被丢弃 |
| 深层 `consume` 拿到 `None` | 中途对组件 slot 调了 `.into_node()`（空白上下文）；用 `cx.child(slot)` |
| `grow` 写在 ctx 组件上没效果 | 同上；属性走"模板再搬运"，`.into_node()` 会绕过它 |

## 7. 自检

```bash
cargo test --example finance                                   # 44 项
cargo test --example shadcn                                    # 14 项
cargo test --example finance -- --ignored dump_boxes --nocapture  # 打印布局盒树
```

其中 `full_toggle_swaps_the_whole_page` 是 FULL 切换的回归：
它走的是"ctx 组件 + `when` 切子树"这条最容易静默失效的路径。

测试里几条是**布局自检**（代替肉眼看截图）：所有容器都有正尺寸、都在视口内、
兄弟盒不重叠；拖分割条后列宽/行高真的变。组件化之后位置全由 flex 决定，
一旦哪个面板忘了 `grow`/`Stretch`，这些测试当场报出来。
