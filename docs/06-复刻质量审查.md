## 1. 打折（语义不等价，已用探针证实）

### 1.1 `ignore_flex` 是死扩展（布局层完全不认）

`node2.rs:1109` 取 `IgnoreFlexChild`，`node2.rs:1130` 把它塞进 **`not_in_layout`
布尔字段**；但 `node2.rs:1196` 又无条件设了 `not_in_layout_fn = Some(..)`，而引擎
`Node::is_not_in_layout()`（`node.rs:859`）**优先读 fn**：

```rust
match &self.not_in_layout_fn {
    Some(f) => f(),          // ← to_node 永远是 Some
    None => self.not_in_layout,   // ← flex_ignore 只落在这里，永远走不到
}
```

布局四处判据（`node.rs:1258 / 1371 / 1416 / 1470`）全走 `is_not_in_layout()`，
所以 `ignore_flex(true)` **对布局零影响**；唯一读裸字段的是
`mve_integration.rs:68` 的 `preseed_cross` 预热，于是它反而把"该子节点跳过宽度
预热"这个**错误副作用**给触发了（其内部文本量不到宽度）。

探针实测（已删）：

```
find IgnoreFlexChild = true
field.not_in_layout=true   is_not_in_layout()=false     ← ignore_flex 到此为止
explicit not_in_layout:   field=false  is_not_in_layout()=true
grow=1 (axis X)                                          ← 对照：exts 通路本身没问题
```

即：TS 的 `ignoreFlex`（不占主轴但仍是普通布局子节点）在 Rust 侧既没有
"不占主轴"的正确语义，又多了一个"跳过预热"的错误副作用。

### 1.2 富文本正文绘制忽略对齐与真实行位置

`rich_text.rs:237` 的 `draw_para` 自己排版面：

```rust
let lh = p.height() / lines.len() as f32;   // 平均行高
let y  = origin.1 + i as f32 * lh;          // 第 i 行 = 平均行高 × i
let mut x = origin.0;                       // ← 起点恒为左内边距，没有行内偏移
...
let (w, _) = measure_text(piece, span.style.font_size);   // 逐片段量宽推进 x
x += w;
```

TS 侧 `drawParagraph(p.paragraph, ctx2, padX, padY)` 是 **CanvasKit 整段栅格化**——
对齐、混排基线、字距全部由排版器给出，不存在这类误差。

探针实测（`build_paragraph` + `rects_for_range(Tight)`，同一段 "abc"、宽 200）：

```
align=Start   tight = (0.00, 32.25)
align=Center  tight = (83.88, 116.12)     ← 排版器已给出居中偏移
align=End     tight = (167.75, 200.00)
```

`draw_para` 起点写死 `origin.0`，所以 `textAlign: Center/End` 画出来仍是左对齐
（高亮矩形用的是 `rects_for_range`，于是**高亮居中、文字靠左**，更明显）。

混排行高探针（10px 行 + 40px 行）：

```
height=57.50 lines=2
line1 真实 top = 11.50   draw_para 给的 y = 28.75     ← 17.25px 偏移
```

即同一段里字号不一致时，行位置会漂、行间会重叠。（纯同字号文本刚好
`p.height()/n == 行高`，所以示例看不出问题——属于"能跑，但一用就错"。）

### 1.3 `rich_text` 的 `size('x')` 在 `!autoWidth` 时不等价

TS `RichTextNode.ts:198`：

```ts
if (d == 'x' && !autoWidth()) {
  const x = layoutValue(node, d);
  if (x.allowSizeFromChildren()) return { value: x.sizeFromChildren(), fromInside: true };
  return { value: layoutValue(parent, d).childSize(node.layoutIndex()), fromInside: false };
}
```

Rust `rich_text.rs:406`：

```rust
Axis::X if !auto_width() => LayoutSize::inside(if avail > 0.0 { w.min(avail) } else { w })
```

差别不在"没暴露 `childSize`"，而在**返回值语义**：TS 走父分配分支时
`fromInside = false`（外包 = 父给的宽），Rust 恒 `fromInside = true`（外包 =
`min(段落宽, inner) + padding`）。于是"父分配 200、文本只有 60 宽"的节点，
TS 宽 200（吃满），Rust 宽 60+padding（缩到文字）。`docs/05 §4.4` 把这处写成
"等价结果、逐像素一致"——**不成立**，是替换公式。

> 同理 `size('y')` 少了 TS 的 `maxFontSizeInSpans() * 1.4` 之外的分支差异，但一致。

### 1.4 `SelectionManager` 根本不是 TS 的模型

TS（358 行）是**纯派生**：管理器持有 `press/release` 两个命中点，
`rangeOf(node)` 每次现算该节点被分配的范围；节点把
`Selectable2`（`selectionRect` / `textLength` / `positionForPoint` /
`textInRange` / `wordRangeAt` / `paragraphRangeAt`）挂到自己身上，管理器全树遍历发现。

Rust（108 行）是**贡献者拼接**：每个节点 `register(sel_cell, get, clear)`，
`recompute()` 把所有非空串用 `\n` 拼起来。

后果：

1. **跨组件拖选做不出来**。引擎的 move 只沿"按下时那条捕获链"派发
   （`mve_integration.rs` 的 `self.capture`），从 A 拖到 B，B 收不到 move，
   它的 `sel` 不会更新——TS 那句"天然支持跨组件选择"在 Rust 侧不成立。
   而 `selection.rs:11` 的注释写着"跨节点的连续拖选……语义与 TS 一致"，是**不实描述**。
2. `Selectable2` 六个方法只实现了 `positionForPoint`（且是私有的），
   `selectionRect` / `textLength` / `textInRange` / `wordRangeAt` /
   `paragraphRangeAt` 全缺 → 谁也调不到 `rangeOf`。
3. 去重键用裸指针 `Rc::as_ptr(sel) as *const ()`（`selection.rs:68`）：
   节点销毁后地址被新 `Rc` 复用，新节点会被判为"已注册"而**静默跳过**。
4. `recompute()` 每次鼠标 move 都把全文 spans 重新 `expand_tabs` 拼接一遍
   （O(全文)/事件），拖选大文本会掉帧。

### 1.5 其余零散打折

| 位置 | TS | Rust | 影响 |
|---|---|---|---|
| `rect.rs:69-100` | `if (w<=0\|\|h<=0) return;` 提前返回，**跳过** `rest.draw` | 零尺寸仍调 `rest_draw` | 小 |
| `nodes.rs:70-96` | 根是完整 `Node2Arg`（`renderCanvas({...rest})`） | `CanvasOpts` 只有 6 个字段，且**自创默认值** `gap:12 / align:Center / align_fix:true / 深色底` | 根节点能力被砍 + 未声明就多出 12px 间距 |
| `element.rs:188` / `node2.rs:1000` | 无 `clip` 字段（用 `drawAtParent`+`acceptClip`） | `clip: bool` 便捷字段，**非读取式**，且裁剪盒是外盒（含 padding），TS 是 inner 盒 | 滚动正文会画进 padding 带（`scroll.rs` 模块注释自认） |
| `node2.rs:1317` | — | `From<Node2> for Slot` 走 `Slot::One(n.to_node())` | 绕过 `mount`，父指针/子节点挂载语义与其它路径不一致，是个陷阱 |

## 2. 取巧与魔法

### 2.1 `scroll()` + `ScrollOpts` 在 TS 里不存在

TS 只有三个原语：`createScroll` / `scrollContent` / `scrollBar`，容器由调用方自己拼。
Rust 多出一个 `scroll(opts, children)`（`scroll.rs:472`）+ `ScrollOpts`（236 行起），
而 `todo2` / `scroll2` 两个示例都建在它上面——**自创 API 成了主路径**。

更麻烦的是 `ScrollOpts` 是 `#[derive(Clone, Copy)]` 的静态值（`thickness` /
`track_color` / `thumb_color` / `thumb_radius` / `width` / `height` / `grow`），
把 P0/P1 刚统一起来的"全读取式"又退回到静态字段，主题/状态改不动。

### 2.2 滚动容器方向被强制反转 + 滚动条手算坐标

`scroll.rs:478`：纵向滚动 → 容器 `Layout::Row`；`scroll_content` 里内容用 `Column`、
偏移落交叉轴。理由（模块注释 ①）是"引擎 `x_fn/y_fn` 是叠加偏移，只在交叉轴抑制
自动对齐"——这是**引擎限制的绕过**，不是 TS 的结构。TS 里 `scrollContent` 用
`position(d)` 覆盖布局位置，容器/内容方向由调用方决定。

连带的第二处：因为容器被改成 Row，滚动条不能像 TS 那样当普通 flex 子节点
（靠 stretch 拿轨道长），于是 `scroll_bar` 改成 `not_in_layout: true` +
手算 `x`/`y`（`scroll.rs:351-366`）。文档称之为"视觉等价"，但
`not_in_layout` 又踩到 §1.1 的字段/fn 诡异，等于给布局埋第二颗雷。

### 2.3 滚轮换算的魔法常量链

- `mve_integration.rs:747`：`PixelDelta → pos / 50.0`（像素变"行"）
- `scroll.rs:48`：`LINE_STEP = 40.0`（"行"变像素）
- 合起来：触控板 100px → 2 行 → 80px；滚轮一格 → 40px。TS 直接吃 `deltaY` 原值。

两个常量互相抵消又都不在 TS 里，是典型的"为了让示例能动"调出来的数。

### 2.4 全局鼠标注册表是空壳，同一件事三份实现

`renderer.rs` 建了 `GlobalMouse2`（down/move/up/wheel 四张表）、`drag_mouse`、
`create_click_counter`，但：

- `drag_mouse` / `create_click_counter` **零调用方**（`grep` 只有 `mod.rs` 的 re-export 和自身单测）；
- `register_down` / `register_wheel` 从未被调用 → clippy `dead_code`；
- 真正需要拖拽的 `scroll_bar`（`scroll.rs:419-450`）自己写了
  `mouse_down/mouse_move/mouse_up` + `Rc<RefCell<Option<..>>>` 会话；
- 真正需要连击的 `rich_text`（`rich_text.rs:441`）用的是**旧的**
  `crate::text_util::ClickTracker`，不是新的 `create_click_counter`。

结论：`docs/05 §5.1` 写"P2 的全局鼠标注册表已可用"，实际是"写好了但没人用"，
而同一能力（拖拽、连击）在另外两处又各实现了一遍。

### 2.5 其它魔法

- `node2.rs:1279` `PARENT_STACK` thread_local 模拟 `ctx.getParent()`：
  依赖"构造顺序 == 挂载顺序"，异步/延迟构造会认错父。
- `rich_text.rs:53` `FC: thread_local FontContext`：全局单例字体上下文，
  与 TS"由调用方传入"不同，多画布/多线程会串。
- `focus.rs` 单例 + `renderer.rs` 单例 + `text_defaults.rs` 单例 + `url_opener.rs` 单例：
  TS 也是模块级单例，这条**不算**问题，但要在文档里写明"单 Canvas 假设"。

## 6. 建议修复顺序

1. **`ignore_flex` 二选一**（半天）：要么在 `to_node` 里把它并进
   `not_in_layout_fn`（`Rc::new(move || flex_ignore || (d.not_in_layout)())`），
   要么删掉 `ignore_flex*` 三个 API——不要留"看起来生效"的假扩展。
   顺手把 `preseed_cross` 的裸字段改成 `is_not_in_layout()`。
2. **`draw_para` 改用行几何**（1 天）：`line.runs()/clusters()` 取
   `visual_offset()` 作行内 x、`line.metrics().block_min_coord`（或 baseline）
   作行 y，`draw_text` 按基线画。这一步同时修好 `textAlign` 与混排行高。
   `wy-text::LineMetric` 需要暴露 `x` / `baseline` 两个字段。
3. **`rich_text::size('x')` 对齐 TS**（半天）：`!autoWidth` 且父已分配时返回
   `LayoutSize::outer(父分配宽)`。需要引擎把 `childSize` 或"已分配宽"暴露给声明层
   （现在 `NodeGeom.inner()` 里有，只是语义是 inner）。
4. **`scroll_bar` 改用 `drag_mouse`**（半天）：把 `renderer.rs` 那套接上，
   顺便让 `register_down/register_wheel` 不再是死代码；`rich_text` 的连击换
   `create_click_counter`，然后删 `text_util::ClickTracker`。
5. **`render_canvas2` 换签名**（半天）：`render_canvas2(rest: Node2Arg, children)`
   与 TS 同构，`CanvasOpts` 降级成调用处的一行 `Node2Arg`；去掉自创的 gap/背景默认值。
6. **`SelectionManager` 按派生模型重写**（2-3 天，依赖 P4）：先补 `Selectable2`
   六个方法，管理器持 `press/release` 命中点；跨节点拖选要引擎把 move 派发给
   "当前悬停链"而不是只发给捕获链（或者派生时用 move 的 hover 命中点，与 TS 同）。
7. 最后再做 P3 `ImageNode` / P4 `EditableTextNode`，然后清 P6 的过渡 impl。

## 7. 值得肯定的部分

- `node2.rs` 的 `Get<T>` / `rest: Node2Arg` / `layout: flex()` / `exts: [grow, align, ignore_flex]`
  三件套是真按 TS 的**读写分离**做的，`to_node` 里 `size`→`from_inside`→padding
  的换算、`width` 覆盖 `size` 的优先级都对（还带注释解释 TS 原文）。
- `element.rs` 的 `node2` 组件把 `Node2Arg` 四十来个字段一条不漏地搬全了。
- `rect.rs` / `wrapped_text.rs` 是这次改动里**最干净的两个文件**：逐句照抄，
  没有自创，没有旧槽位（`rect` 唯一偏差是零尺寸时仍调 `rest.draw`）。
- `wy-text::build_paragraph` 的 `maxLines + ellipsis` 是真实现（二分最长可见前缀 +
  省略号重排 + 进缓存），不是把参数改个名字糊过去。
- 三个示例都能跑，图元数正常（`canvas2_text` 44 / `scroll2` 393 / `todo2` 107），
  `scroll2` 的"缩窗口就能滚"确实修好了（`grow` + 不写死高度）。

**本轮新发现并修复的两个结构性 bug**（复刻 TS `ctx.addNode` / `sizeFromChildren` 时暴露）：

- **挂载期父登记缺失**：TS 的 `node2` 体在拿到 ctx 时才跑，`node.parent = ctx.getParent(); ctx.addNode(node)` 在那一刻建立父子关系；Rust 的 `Node2` 对象在 `.of()`/`build` 时就建好（那时还没有父），此前挂载从不上报 → `children()` 恒空。修复：`Node2::mount` 按"上下文携带的父指针（动态区域）→ 线程局部父栈（静态）"登记自己，对应 TS 那两句。
- **动态区域认不到父**：`render_for_each`/`render_when` 的 creater 在惰性求值时才跑，线程局部父栈早已弹空。修复：`NodeContext` 增加 `node2_parent`，随 `render_for_each` 参数带进 creater 的子上下文（`inherit_with_parent`）。
- 由此 `size()`（TS `sizeFromChildren`）改为**纯声明式**计算：显式 `size` 闭包 → 显式宽高 → 子节点沿轴累加（主轴 + gap×(n−1)，交叉轴取最大），不再经 `to_node()` 二次物化（`child_fcs` 挂载时已消费，二次展开必空——正是旧实现 `contentSize` 恒为 0 的根因）。

**验证**：wy-mve 194 / wy-text 98 / wy-engine 113 全绿；`scroll2` 出图确认滚动条出现（内容 1436px、视口 642px、滑块 287px、393 图元）；全部示例 `cargo check` 通过。
