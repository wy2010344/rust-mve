# 07 · 旧体系迁移实测（shadcn：v1 → canvasRender2，已完成）

> 目的不是新增示例，而是回答一个问题：**旧 `rsx!` + `#[component]` + v1 `Node`
> 能不能整块换到 `#[rec]` + `node2!` + `Fc`，并把旧实现删干净？**
>
> 答案：**能，已经删了**。`crates/wy-app/examples/shadcn/` 现在只有一个版本，
> 纯 canvasRender2：入口 `Node2App` + `build_root_node2`，组件 `#[rec]` + `!` 宏，
> 输入框 `editable_text_node`，滚动 `create_scroll`，浮层
> `canvas_render2::{dialog, dropdown}`。
>
> 这个示例里**没有任何 v1 符号**：无 `rsx!`、无 `#[component]`、无 `Node`、无
> `current_box()`、无 `text_field_opts`、无 `#[path]` 跨目录借文件。
> 它同时是"删 `rsx.rs` + `component.rs`（1739 行）"的最后一个前置样例。

## 二、10 条必须知道的差异

### 1. `#[rec]` 的 `!` 宏只能找到 crate 根上的 `XxxProps`

宏体里是 `$crate::XxxProps`，而 `$crate` 指**导出该宏的 crate 根**，指向不了
定义所在的子模块。组件写在子模块里就必须把 props 再导出：

```rust
// main.rs
#[doc(hidden)]
pub use widgets::{ButtonArg, CardArg, TextLabelArg /* .. */};
```

漏了就是 `E0433: cannot find XxxProps in the crate root`。这不是本示例特例，
是 `#[macro_export]` 的固有约束。

> 顺带两条：`#[macro_export]` 由过程宏生成时**同 crate 内不能用绝对路径**引用
> （`crate::stat_card!` 报 "macro-expanded macro_export macros cannot be referred
> to by absolute paths"），裸名 + `#[macro_use] mod` 可行；而 `#[macro_use]` 的
> 可见性**按声明顺序**，提供宏的模块必须排在消费者之前。

### 2. `!` 宏的 getter 参数写**表达式**，不是闭包

```rust
// 旧 #[component]：getter 收闭包
stat_card { value: move || visits.get().to_string() }

// 新 ! 宏：宏自己包 move ||，写表达式
stat_card! { value: visits.get().to_string() }
```

写多一层闭包会得到 `Fn() -> closure`，报 `String: From<{closure}>` 不满足。

### 3. 尺寸用 `n.width()` / `n.height()`，**不要** `n.geom()`

上一轮（走 `MveApp` 时）的结论是反的：那时 `geom()` 是 v1 引擎在布局期回填的
缓存，`width()` 反而拿不到父级 `grow` 的分配结果。

切到纯 `Node2App` 后彻底翻转：

- **没有任何东西写 `geom`**（全库只有 `mve_integration` 写它）→ `geom()` 恒为 0；
- `width()` 走 `declared()` → `defaultSize`（父布局实时分配），是 Node2 自己的
  真相源，`render_node2` 本身也用它。

这就是"v2 不向 v1 妥协"的具体表现：`geom` 是 v1 管线的产物，碰它就是妥协。

### 4. `align_fix` 的判断口诀（本轮踩了两次）

`align_fix: true` = **交叉轴尺寸取父给的**。它不是"让父分配尺寸"的万能开关：

| 容器处境 | 该不该 `align_fix` |
|---|---|
| 交叉轴由父分配（`Stretch` 子项、有 `grow` 的主轴子项） | ✅ 要 |
| 交叉轴由内容决定（主轴无 grow 的普通子项） | ❌ 不要，否则 `height()` 回头问父分配，父又要先量它 → 环闭合取 0 |
| 容器**自己声明了交叉轴尺寸**（`height: 30` 的行），子节点要 `Center` / `End` | ✅ 要，否则"居中"的基准会变成最高子节点 |

具体到这个示例：
- 主体行 / 表单待办行 / 右侧列：**要**（它们的交叉轴来自父）；
- 统计行：**不要**（它是右侧列的主轴子项、无 grow，高度由三张卡的内容撑开；
  加了之后整行塌成 0，被下面的卡片盖住——现象是"统计卡只剩一条"）；
- 待办行（`height: ROW_H = 30`，`Center`）：**要**。这是第三行表格那条，
  也是本轮"待办每行整体偏上"的真因：

  ```
  alignFix = true  → StackLayout.size() = 容器高 30 → checkbox(18) 落在 (30-18)/2 = 6
  alignFix = false → StackLayout.size() = max(子节点) = 24（删除按钮）
                   → checkbox 落在 (24-18)/2 = 3，相对整行**偏上 3px**
  ```

  TS `wy-helper/src/layout/stack.ts` 与 Kotlin `StackLayout.kt` 是同一套
  （`alignFix ? innerSize : max(child.outerSize)`），所以这不是 Rust 独有：
  **三边都要求"给了交叉轴尺寸就写 `alignFix = true`"**。Kotlin 组件里
  `override val alignFix get() = true` 到处都是（`Button` / `Dialog` /
  `Popover` / `SegTabs` …），就是这条约定；漏写不报错，只差几像素，很难归因。
  库侧有回归：`geometry::tests::stack_align_fix_decides_centering_reference`。

### 5. 显式 `width: 0.0` 就是**真的 0 宽**

v1 里 `size: (0,0)` + `align_self: Stretch` 表示「flex-basis 0，交叉轴由父拉伸」。
新体系里 `width: 0.0` 是硬声明，父级 `Stretch` 不会覆盖它 → 节点宽度 0。

「交给父」只能靠**不声明**。所以 `separator` 这种「横线要撑满」的组件，
不能写 `width: 0.0`，要干脆不写 `width` 字段。

### 6. `editable_text_node` 要包一层容器，且宽度必须「一级一级传下去」

两个原因（TS `EditableTextNode.ts` 同款，不是 Rust 移植偏差）：

- 它的 `draw` 是**整段覆盖**的（TS 末尾 `merge(p, { nodeRef })` 也覆盖 `arg.draw`）
  ——传进去的边框/背景绘制会被丢掉；
- 它自己声明了 `size`（= 内容宽），**主轴 `grow` 分不到它头上**，只有交叉轴
  `Stretch` 能覆盖。

标准形态：外层容器画边框 + 抢宽度份额，内层编辑器只管文字（见
`shadcn/dashboard.rs::input_field`）。

宽度是全篇最容易反复的地方，三条实测结论：

1. **外层容器**要有宽度来源：作为列的交叉轴子项靠父级 `Stretch`（表单卡就是
   这样），作为行的主轴子项则要自己 `exts: vec![grow_xy(1.0, 0.0)]`。
2. **外层容器自己也要 `align_fix: true`**（列 → 取父给的宽）或
   `direction_justify: Start`（行 → 宽度改问父分配）。默认的 `Grow` 加"没有
   grow 子节点"会让 `allowsSizeFromChildren` 为真，宽度退回"内容宽"，而此刻
   内层编辑器还没拿到宽度 → 0。
3. **不要在中间再套一层带 `grow` 的容器**。曾经的写法是
   `grow 容器 → input_field(exts: vec![])`：容器确实分到了宽度，但 `input_field`
   在内层没有 `grow`、没有 `width`，`defaultSize` 又回头问父 → 环闭合取 0，
   连边框都画不出来（待办卡片里就只剩一个孤零零的「添加」按钮）。
   要传就把 `grow` 直接给 `input_field`。

内层编辑器自己用 `width: 外层.width()` 读回来——`Ref2` 在 build 后写槽、
`children` 的 `Fc` 到挂载才展开，所以先建外层再挂内层的顺序是安全的。

**内边距要留在编辑器自己身上，不要放外层容器。** 命中测试只认节点自己的矩形
（`accept_hit`）：padding 在外层时，靠边那 10px 属于"容器空白"，命中链里没有
可聚焦节点 → 指针路由把焦点清空，用户感知就是"点输入框边缘点不进去 / 没有光标"。
`dashboard.rs::input_field` 现在把 `padding_inline_start/end` 传给内层编辑器
（与 `node2/todo.rs::text_field` 一致），整块矩形都是编辑器，点哪儿都能聚焦。
回归：`clicking_the_input_padding_still_focuses_the_editor`（把 padding 挪回外层
即失败，已反向验证）。

### 7. 构建期展开必须走 `raw_children()`，`hide` 只在运行期生效

`children()` 会滤掉 `hide()` 为真的子节点——那是**运行期**语义（不绘制、不命中、
不进焦点链）。但 `expand_node2` 若也按它递归，关闭状态的浮层（`hide == true`）
的子孙永远不会被展开；等 `open` 变 true 时面板里是空的。

一次性建树 + 运行期显隐的声明式浮层对此零容忍，所以展开走原始列表。这条是
本轮对 `Node2` 运行时的**库级修复**（`node2/mount.rs`）。

### 8. 布尔开关不是 `Option`，`rest.<开关>` 直接是 `Get<bool>`

节点参数（`Node2Props`）里带默认值的读取式开关 —— `hide` / `not_in_layout` /
`selection_enabled` / `skip_draw` / `focusable` / `focus_trap` —— 存储类型是
`Get<bool>`（缺省 `always(false)`），**不是** `Option<Get<bool>>`。

这条是被一次真实故障逼出来的：早先中间还有一层 `Node2Arg`，开关在那一层是
`Option<..>`，声明层的收口函数又对所有带默认值的开关一律包 `Some(..)`，于是

```rust
if rest.focusable.is_none() { rest.focusable = Some(always(true)); }  // 死代码
```

永远不命中，`editable_text_node` 一直不可聚焦 → `pointer::down` 的
`focusable_leaf_of` 挑不到目标 → 点输入框等于点空白 → `active_editor` 为空 →
键盘路由没有消费目标、`ime_allowed()` 也是 `false`（中文输入法都不启用）——
**一个字都打不进来**。

现在没有 `Option` 可判：想覆盖就直接 `node2! { ..rest, focusable: true }`。
"调用方传没传"这个问题本身就不该问——默认值已经在声明层算好了，缺省就是
`false`，再区分"没写"与"写了 false"没有任何语义。

回归测试两条：

- 库级 `editable_text_node::tests::editor_is_always_focusable`；
- 端到端 `clicking_the_input_then_typing_writes_the_signal`：`Node2App` 收
  `CursorMoved` / `MouseInput` → 焦点落到编辑器 → `handle_key_event` 打一个字符
  → 信号里出现该字符 → 退格再删掉。

### 9. 组件内部写 `node2! { ..rest, .. }`，不要手搓节点

`#[rec(extends = node2)]` 注入的 `rest` 就是一份完整的 `Node2Props`，
`Node2::build` 直接吃它。所以组件体只该写**差异**：

```rust
#[rec(extends = node2)]
pub fn rect_node(background: Option<Color>, ..) -> Fc {
    let rest_draw = rest.draw.clone();
    node2! {
        ..rest,                    // TS 的 `...rest`
        node_ref: node_ref.clone(),
        draw: move |s, n| { ..; if let Some(f) = &rest_draw { f(s, n) } },
    }
}
```

三条要点：

1. **`..rest` 必须写在最前面**：它按值展开整份 props，写在中间会被右边的 setter
   抢先覆盖，语义就反了；
2. **追加用 `exts_push`**：`..rest` 会带回调用方的 `exts`，`exts_push` 是 `Vec`
   字段的追加 setter（覆盖式 `exts:` 会把它冲掉）。编辑器就是靠它挂
   `ImeExt` + 编辑器句柄两条扩展；
3. **只 clone 要回带的字段**：`rest.draw.clone()` 取旧绘制，其余仍按值展开——
   `Node2Props` 整体不可 `Clone`（里面有必填普通字段），只 clone 一个 `Rc` 字段
   才是对的。

`Node2::empty().build(props)` 仍然合法，只有一个例外：`rich_text` 这类
**构造期就要节点句柄**的组件（选区管理器要 `bind(&node, ..)`、`geom` 要
`node.node_ref()`）。TS 那边靠 `tfc` 注入 `node` 实现，Rust 用
`empty + build` 等价，不算过程式。

### 10. 文本一律是**子节点**，不在 `draw` 里 `draw_text`

`Scene::draw_text` 画完就没了：父布局不知道这段字多高、多宽，于是所有
"居中 / 靠右 / 徽章宽度" 都只能手算坐标和 `measure_text`——一旦字号或字体
变了就错位，而且**父容器没法用文本撑尺寸**。

所以组件里的文案一律是 `text_label!`（= `wrapped_text_node!`）子节点：

```rust
// ✅ 容器画底，文本是子节点：宽度由 padding + 文本自然宽撑出来，位置由 flex 算
node2! {
    height: H,
    padding_inline_start: 8.0,
    padding_inline_end: 8.0,
    layout: flex! { direction: Layout::Row, align_item: AlignItem::Center, align_fix: true },
    draw: move |s, n| s.fill_round_rect(Rect::new(0.0, 0.0, n.width(), n.height()), 4.0, bg),
    children: vec![text_label! { content: text(), font_size: 12.0, color: fg }],
}

// ❌ 手绘：宽度自己量、基线自己猜、父布局什么都不知道
node2! {
    width: measure_text(&text, 12.0).0 + 16.0,
    draw: |s, _| { s.fill_rect(..); s.draw_text(Point::new(8.0, 4.0), &text, 12.0, fg) },
}
```

`wrapped_text_node` / `rich_text` 的 `size(d)` 就是这个"文本撑起来的尺寸"：
- X：`auto_width: true` 时 = 段落自然宽；
- Y：= 段落高（含行高）。

父容器读到它就能排（`grow` 分配宽度、`Center` 居中、`sizeFromChildren` 撑高），
不用任何人再算一次。

本轮把 shadcn 里所有 `draw_text` 都换掉了：`button` / `badge` / `tabs` /
`avatar` / `stat_card`（标题、数值、变化徽章）/ `sidebar` 导航项 / 「更多菜单」
/ 下拉菜单项。现在这个示例里**没有一处手绘文本**。

第二轮扫尾（同一规则推广到其它示例）：

| 文件 | 换掉了什么 | 组件 |
|---|---|---|
| `node2/todo.rs` | 行文本（含删除线）、剩余计数、"×" 删除钮 | `text_label!`（新增 `examples/node2/text_label.rs`，与 shadcn 同一份契约） |
| `ooc_preview.rs` | `pane` 标题、`tab_btn` 文案、自选行三列 | v1 的 `text_styled` / 新增 `text_with_color`（颜色是 getter） |

删除线是个有意思的例外：线要按**文字实际占的宽度**画，所以容器在 `draw` 里
读 `n.children()[0].width()`——布局已完成，这就是"文本撑起来的尺寸"的直接用法，
比再 `measure_text` 一次更可靠。

`ooc_preview` 走的是 v1 组件，这里补的是同类物：`text_with_color(content, size,
color_getter)`——`text_styled` 把颜色定死在构造期，"选中变色"就得重建节点；
换成颜色 getter 后只重绘。顺带给 v1 `Node` 补了 `with_justify` / `with_align_fix`
两个 builder：只居中一个定尺寸容器里的文本时，`align_items` 只管交叉轴，主轴和
`alignFix` 都得显式给（同 docs 第 4 条）。

> 仍有手绘文本的地方：`node2/abs.rs`（演示画布原语的 demo，文本就是原语本身）
> 与 `finance/`（还挂在 v1 声明层上，整体迁移时按同一条规则处理）。

> 图标仍然走 `draw`（`draw_icon_at`）：那是矢量路径，不是文本，没有
> "字号 / 行高"这回事。但图标也做成**定尺寸子节点**，位置同样交给 flex
> （`button` 的图标、侧栏导航的图标都是这样），这样"图标 + 文案"整行对齐
> 也只靠 `align_item: Center`。

## 三、浮层：这轮补了什么

v1 的 `dialog` / `dropdown` 是 `overlay.rs` 里的 `#[component]`，自带遮罩、
锚点翻转、Esc 关闭。v2 侧补了两块：

| 新增 | 对应 TS / 旧实现 |
|---|---|
| `canvas_render2/placement.rs`（`resolve_placement`） | TS `canvasCore/Placement.ts`（8 方向 + 翻转 + 贴边，纯几何，10 条单测） |
| `canvas_render2/popover.rs`（`dialog` / `dropdown`） | TS `helper/Popover.ts` 的 `popoverPanel` + v1 `overlay.rs` 的两种形态 |

实现要点（每条都是踩出来的）：

1. **浮层根 `not_in_layout` + 显式 `x`/`y`**：不参与布局的节点没有位置可分配，
   `x()`/`y()` 若落到 `default_position` 会去要 `layout_index()`，而它对该类节点
   是硬性错误（TS 同款 throw：`当前节点不在Layout中`）。
2. **尺寸取父 inner**：`size(axis) = inner_size(parent, axis)`——浮层挂在画布根
   下时就是整窗，挂在页面里就只是内容区（所以入口必须把它们挂根上）。
3. **面板尺寸由内容**：不写 `size`，让 `default_size` 走
   `allows_size_from_children`（列容器 + 无 grow 子）。TS 显式写
   `size(d) => sizeFromChildren(..)` 是因为它的 `sizeFromParent` 会抛；Rust 的
   `default_size` 先判定再走，不必重复表达。
4. **位置在 `position` 消息里算**：dialog 居中；dropdown 交给
   `resolve_placement`（面板尺寸取 `width()/height()` 实测，故菜单项增减也能
   正确翻转）。
5. **三条关闭路径**：点遮罩/空白（浮层根 `mouse_click`，面板自己
   `stop_propagation`）、焦点在浮层内时的 Esc（`handle_key`）、焦点不在时的
   Esc（`register_key_press` 全局旁听，对应 v1"焦点链未消费即广播"）。
6. **`debug_name`**（"dialog" / "dialog-panel" / "dropdown" / "dropdown-panel"）：
   调试与测试按名字定位，不参与求值。

## 四、还差什么

- **`finance`**（约 8000 行，是 shadcn 的 3 倍，大量自绘图表）：它是删
  `rsx.rs` + `component.rs` 的最后一个前置。清单见下。
- **`spacer` / `scroll` 的小封装**：现在每个示例都在手拼
  `create_scroll + content + bar`，值得收一个 `scroll_view!(..)`；
- **focus 边框高亮**：v1 `TextFieldColors::focus_border_color` 由组件按焦点状态
  切换；v2 编辑器有焦点句柄（`is_focused()`），示例里还没接。
  （`scroll_bar` 的短内容已在截图里确认：内容短于视口时滑块占满整条轨道。）

### `finance` 迁移清单（实测计数，`ui/` + `main.rs`）

| v1 用法 | 次数 | v2 对应 |
|---|---|---|
| `rsx! { .. }` | 66 | `node2! { .. }` |
| `#[component] fn .. -> Node` | 24 | `#[rec] fn .. -> Fc` |
| `.into_node()` | 34 | 直接是 `Fc`，不需要收尾 |
| `Slot`（children 类型） | 37 | `Vec<Fc>` |
| `current_box()` | 27 | `draw` 的第二个参数 `n.width()` / `n.height()` |
| `theme::text/text_right/text_center` | 24 | `text_label!` / `text_with_color` 子节点 |
| `cols_row` / `cols_row_at` | 15 | 每列一个文本子节点 + `grow` 撑开 |
| `ctx.provide` / `ctx.consume` | 4 / 11 | 同左（`NodeContext` 与运行时无关），或改显式参数 |
| `for_each` / `when` / `scroll {` | 3 / 2 / 4 | `for_each_node` / `if_node` / `create_scroll` 三件套 |
| `on_down` / `on_up` / `on_move` | 30 | `mouse_down` / `mouse_up` / `mouse_move`（拖拽要 `*_capture`） |

三个结构性前提（不是逐行替换能解决的）：

1. **运行时**：`main.rs` 的 `Dashboard { inner: MveApp, .. }` 包着 v1 app 做
   tick 驱动；v2 侧要换成 `Node2App::new(|vp| build_root_node2(..))` 并把
   `next_wake` / `on_wake` 的行情 tick 逻辑搬到 `WyApp` 实现上。
2. **v2 树不接受 v1 `Node`**：`build_root_node2` 会 `set_node2_only(true)`，
   `From<Node> for Fc` 只在 v1 上下文里成立。所以**不能逐文件混编**，只能整块
   切换（可以并排放 `ui2/`，最后一并替换）。
3. **拖拽分栏**：v1 靠 `on_down`/`on_up` + 自己存起点；v2 要用
   `mouse_down_capture` / `mouse_move_capture` 抓指针，并注意 `gutter` 的
   `grow` 是权重不是像素（现有实现就是这个语义，搬过去即可）。

建议分三期，每期都能出图对比：P1 外壳 + 顶栏 + 自选 + 统计（`panel` /
`text_label` / `chip` / `kv_row` 这些原语也一并换掉）；P2 盘口 + 成交 +
深度；P3 K 线 + 分栏拖拽 + `main.rs` 切换运行时、删 `ui/`。
